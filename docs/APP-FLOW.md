# APP FLOW — 流程和界面

## 页面 / 画面清单
本项目以合约和命令行为主，网页是可砍项。

| 画面 | 用途 | 谁能进 |
|---|---|---|
| 命令行脚本（必做） | 部署、建池子、下单、推动价格、跑延迟测量 | 持有部署钱包的人 |
| 订单页（可砍） | 连钱包，下 OCO 单，看自己的订单和状态，取消 | 任何连了钱包的人；没连钱包也能看价格 |
| 链路时间线（可砍，和订单页同一页） | 显示最近一次成交的三笔交易和各段耗时，带浏览器链接 | 任何人 |
| 演示推价格（同一页，标明仅测试网演示） | 用连上的钱包在池子里做一笔 swap，把价格推过订单的触发线 | 持有测试代币的钱包 |

**网页的一次演示**
1. 打开页面，看到当前价格（tick）。点"连接钱包"，钱包不在 Unichain Sepolia 时请它切换。
2. 填数量、止损和止盈（相对当前 tick 的格数），点"下单"：代币授权不够时先发授权，再发下单交易。
3. "我的订单"里出现这张单，状态"活跃"；几秒后显示"Reactive 已跟踪"。
4. 在演示区点"把价格推下去"（或"推上去"），发一笔 swap。
5. 时间线依次出现：swap（Unichain Sepolia）→ reactive 交易（Lasna，写明触发的是哪张订单、哪一种触发）→ 这张订单的成交（Unichain Sepolia），每步带链接。swap 到成交用同一条链的区块时间戳相减；Lasna 那一步只显示本页大约什么时候看到，页面靠轮询，误差几秒，偏早偏晚都有可能，页面上注明。订单状态变成"已成交"。
6. 时间线跟的是"这笔 swap 之后，第一张被 reactive 合约触发的、属于你的订单"，成交只查这一张；不保证触发就是这笔 swap 引起的（别人的 swap 也可能触发）。如果触发的是过期，时间线到"请求关闭"为止。页面刷新后时间线清空，订单状态仍从链上读。

## 主要流程
**下单并自动止损**
1. 用户授权金库使用代币，调用 `createOrder`。
2. 金库收走代币，发 `OrderCreated`。
3. Lasna 上的 reactive 合约收到该事件，记下订单。
4. 有人在池子里交易，价格跌破止损价，池子发 `Swap`。
5. reactive 合约收到 `Swap`，判断触线，请求 callback，订单标记为待确认。
6. 金库收到 callback，复核价格，卖出，把所得转给用户，发 `OrderExecuted`。
7. reactive 合约收到 `OrderExecuted`，移除订单。

**止盈**：同上，第 4 步改为价格涨破止盈价。

**移动止损**：第 5 步里价格创新高时只更新最高价，不触发；从最高价回落超过设定距离时触发。

**取消**：用户调用 `cancelOrder`，金库退回代币，发 `OrderCancelled`，reactive 合约移除订单。

**过期**：过了过期时间戳，callback 到达也不成交；用户调用 `reclaimExpired` 取回代币。

**延迟测量**：脚本下单 → 发一笔推动价格的 swap → 等三笔交易上链 → 记录各自的区块时间戳和本机观测时间 → 重复 30 轮以上 → 输出 p50 / p95 和 CSV。

## 状态和例外
| 情况 | 表现 |
|---|---|
| 订单状态 | 活跃、待确认、已成交、已取消、已过期 |
| callback 到达时价格已回到线内 | 不成交，订单回到活跃，可再次触发（带冷却时间，按时间戳） |
| callback 到达时订单已取消、已成交或已过期 | 直接返回，不 revert，不重复卖出 |
| 成交量低于最小成交量 | 不成交，订单回到活跃 |
| 非 callback proxy 或非指定 reactive 合约调用 `execute` | revert |
| 活跃订单数达到上限 | `createOrder` revert，提示已满 |
| reactive 合约或金库有欠款 | 收不到事件或 callback；README 写明怎么查欠款和补款 |
| 网页：未连钱包 / 无订单 / 交易失败 | 分别显示"请连接钱包" / "还没有订单" / 失败原因和交易链接 |
| 网页：没有浏览器钱包 / 钱包在别的链 / 用户拒签 | 提示安装插件 / 请求切换到 Unichain Sepolia / 显示"已取消"，不当成错误 |
| 网页：止损不低于当前价、止盈不高于当前价、已有 3 张活跃单 | 发交易前就在页面上提示，不浪费 gas |
| 网页：RPC 读取失败 | 显示哪一步读失败；价格每 15 秒自动重读，订单列表点"Refresh"重读；不清空已显示的数据 |
| 网页：订单一直没被 Reactive 跟踪 | "没跟踪"要连续 3 次读取（间隔 1 秒）都一致才算（落后的节点可能短暂答错）。本页下单后 2 分钟内显示"not tracked yet"，超过 2 分钟显示"not tracked after 2 minutes: cancel and place again (see README)"（被 20 张上限丢掉或欠款期间漏掉了创建事件）；别处下的单或刷新前下的单不知道下单时间，只显示中性的"not tracked (if just placed, wait a minute; if it stays, see README)"，不建议撤单 |
| 网页：上一笔操作还没结束又点按钮 | 按钮都是禁用状态；万一点到，显示"另一笔操作还在进行" |

## 界面规范
网页如果做：单页，系统字体，深浅色跟随系统，不用组件库。无设计稿。手机宽度也能用（左右留 16px，不横向滚动）。界面文字用英文（评委多为英文读者）。
