# APP FLOW — 流程和界面

## 页面 / 画面清单
本项目以合约和命令行为主，网页是可砍项。

| 画面 | 用途 | 谁能进 |
|---|---|---|
| 命令行脚本（必做） | 部署、建池子、下单、推动价格、跑延迟测量 | 持有部署钱包的人 |
| 订单页（可砍） | 连钱包，下 OCO 单，看自己的订单和状态 | 任何连了钱包的人 |
| 链路时间线（可砍） | 显示最近一次成交的三笔交易和各段耗时，带浏览器链接 | 任何人 |

## 主要流程
**下单并自动止损**
1. 用户授权金库使用代币，调用 `createOrder`。
2. 金库收走代币，发 `OrderCreated`。
3. Lasna 上的 reactive 合约收到该事件，记下订单。
4. 有人在池子里交易，价格跌破止损价，池子发 `Swap`。
5. reactive 合约收到 `Swap`，判断触线，请求 callback，订单标记为待确认。
6. 金库收到 callback，复核价格，卖出，把所得转给用户，发 `OrderExecuted`。
7. reactive 合约收到 `OrderExecuted`，移除订单。

**止盈**：同上，第 4 步改为价格涨破止盈价。

**移动止损**：第 5 步里价格创新高时只更新最高价，不触发；从最高价回落超过设定距离时触发。

**取消**：用户调用 `cancelOrder`，金库退回代币，发 `OrderCancelled`，reactive 合约移除订单。

**过期**：过了过期时间戳，callback 到达也不成交；用户调用 `reclaimExpired` 取回代币。

**延迟测量**：脚本下单 → 发一笔推动价格的 swap → 等三笔交易上链 → 记录各自的区块时间戳和本机观测时间 → 重复 30 轮以上 → 输出 p50 / p95 和 CSV。

## 状态和例外
| 情况 | 表现 |
|---|---|
| 订单状态 | 活跃、待确认、已成交、已取消、已过期 |
| callback 到达时价格已回到线内 | 不成交，订单回到活跃，可再次触发（带冷却时间，按时间戳） |
| callback 到达时订单已取消、已成交或已过期 | 直接返回，不 revert，不重复卖出 |
| 成交量低于最小成交量 | 不成交，订单回到活跃 |
| 非 callback proxy 或非指定 reactive 合约调用 `execute` | revert |
| 活跃订单数达到上限 | `createOrder` revert，提示已满 |
| reactive 合约或金库有欠款 | 收不到事件或 callback；README 写明怎么查欠款和补款 |
| 网页：未连钱包 / 无订单 / 交易失败 | 分别显示"请连接钱包" / "还没有订单" / 失败原因和交易链接 |

## 界面规范
网页如果做：单页，系统字体，深浅色跟随系统，不用组件库。无设计稿。
